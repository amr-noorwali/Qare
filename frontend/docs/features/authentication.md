# التسجيل والدخول في الواجهة

## الحالة الحالية

صفحتا `/register` و`/login` تستخدمان نموذجًا واحدًا. بعد نجاح طلب Go، تحفظ الواجهة الرمز في `localStorage` بالمفتاح `qare_token` ثم تنتقل إلى `/library`. الترويسة تطلب بيانات المستخدم إذا وجدت الرمز، وتزيله محليًا عند الخروج.

النموذج والترويسة يستخدمان الآن أسلوبًا أبيض وأسود واسم المنصة «قارئ»، مع لوحة زجاجية وصورة خلفية محلية لصفحات الحساب. تظهر اللوحة بحركة CSS قصيرة وتستجيب الأزرار بحركة طفيفة عند التفاعل، مع بقاء المحتوى مرئيًا ودعم تقليل الحركة. حجم التسميات والأزرار 16px، ونص الشرح 17px بتباعد أسطر نسبي؛ راجع [مقياس الهوية](visual-identity.md). بقيت الحقول والإرسال والتنقل كما هي.

## الملفات والارتباطات

| الملف | الدور |
|---|---|
| `app/register/page.tsx`, `app/login/page.tsx` | تعريف مساري Next.js وتركيب `AuthForm` |
| `components/auth-form.tsx` | الحقول، التحقق الأساسي من المتصفح، حالات الإرسال والخطأ، حفظ الرمز والتنقل |
| `components/header.tsx` | عرض حالة الدخول، استدعاء `auth.me`، وزر الخروج |
| `lib/api.ts` | `auth.register`, `auth.login`, `auth.me`, `token`, وترويسة Bearer |
| `app/library/page.tsx` | وجهة ما بعد الدخول؛ تقرأ الرمز بعد التحميل لتجنب خطأ Hydration |

## الاتصال بالباك إند

`POST /api/auth/register` و`POST /api/auth/login` و`GET /api/auth/me`. يوجد `POST /api/auth/logout` في Go لكن زر الواجهة لا يستدعيه حاليًا. تفاصيل قواعد التحقق والجلسات في [الملف الشامل](../../../docs/features/authentication.md).

## غير مكتمل

لا توجد Cookie محمية أو استعادة كلمة مرور. الخروج يمسح الرمز من المتصفح فقط. لا يوجد مجلد كود خاص بالمصادقة؛ المكونات وخدمة API مشتركة وفق بنية Next.js الحالية.
