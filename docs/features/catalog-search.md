# تصفح الكتب والبحث

توثيق التنفيذ داخل مشروع الواجهة: [frontend/docs/features/catalog-search.md](../../frontend/docs/features/catalog-search.md).

## الحالة الحالية

تعرض الصفحة الرئيسية الكتب للجميع دون تسجيل دخول. يمكن البحث بجزء من العنوان أو اسم المؤلف. ترسل الواجهة الطلب بعد توقف الكتابة 250 مللي ثانية، وتعرض حالات التحميل والخطأ وعدم وجود نتائج. تتبع عناوين الصفحة وبطاقات الكتب وحقل البحث مقياس الخط المركزي في [الهوية البصرية](visual-identity.md).

تحتوي الصفحة الرئيسية أيضًا على افتتاحية بصورة كومة الكتب المقدمة من المستخدم، مع عرض شفاف أصغر فوق الخلفية البيضاء وحركة CSS قصيرة للنص والصورة، ثم عرض الكتب، قصة قارئ بصورة اليدين والكتاب المقدمة من المستخدم، شرح تصنيفات المكتبة، ودعوة لإنشاء حساب. تظهر البطاقات بحركة خفيفة عند تحميلها، وتتفاعل الأزرار والبطاقات عند المرور، ويُستخدم تأثير تمرير CSS اختياري في المتصفحات الداعمة مع بقاء المحتوى مرئيًا. زر البحث في الافتتاحية ينتقل إلى حقل البحث في الصفحة نفسها عبر `#book-search`. هذه الأقسام واجهة فقط؛ لم تُضف تجارة إلكترونية أو عضوية مدفوعة.

## مسار العمل والارتباطات

في الفرونت، `app/page.tsx` يحتفظ بنص البحث وحالة التحميل والنتائج، و`components/book-card.tsx` يعرض الكتاب، و`lib/api.ts` يرسل الطلب. لا يوجد مجلد ميزة مستقل؛ راجع [خريطة الفرونت إند](frontend-map.md).

الأقسام الثابتة للصفحة الرئيسية في `frontend/components/landing/hero.tsx`, `story-section.tsx`, `reading-paths.tsx`, `membership-cta.tsx`. بطاقة الكتاب الآن أحادية اللون وتستخدم تحميلًا كسولًا للغلاف. البحث وحالاته ما زالت في `app/page.tsx`.

`frontend/app/page.tsx` → `books.list(q)` في `frontend/lib/api.ts` → `GET /api/books?q=...` في `backend/internal/routes/routes.go` → `Books` في `backend/internal/handlers/api.go` → استعلام `Books` في `backend/internal/repositories/books.go` → جدول `books` مع متوسط وعدد المراجعات من `reviews`.

تعرض `frontend/components/book-card.tsx` الغلاف والعنوان والمؤلف والنوع والمتوسط وعدد المراجعات، وتربط البطاقة بصفحة [تفاصيل الكتاب](book-details.md). تُدرج ستة كتب أولية عبر `seed` في `backend/internal/repositories/database.go` عند إنشاء قاعدة فارغة.

## API والبيانات

- `GET /api/books`: كل الكتب؛ لا يتطلب دخولًا.
- `GET /api/books?q=النص`: بحث `LIKE` في `title` أو `author`، وترتيب النتائج حسب `id`.
- بيانات البطاقة: `id`, `title`, `author`, `description`, `cover_url`, `genre`, `average_rating`, `review_count`.
- يتغير المتوسط وعدد المراجعات عند إضافة مراجعة أو حذفها؛ انظر [المراجعات](reviews-ratings.md).

## غير موجود أو غير مكتمل

- لا توجد إضافة/تعديل/حذف كتب من الواجهة أو API، ولا ترقيم صفحات أو فرز أو فلاتر نوع.
- البحث الحالي يعتمد `LIKE` مع `%` في الطرفين، وهو مناسب للبيانات الصغيرة فقط.
- روابط الأغلفة خارجية؛ لا توجد خدمة رفع أو نسخة محلية للأغلفة.

## تشخيص خطأ Hydration في حقل البحث

إذا كانت الصفحة تفتح ولكن الكتب لا تظهر، افحص استجابة `GET /api/books` وملفات `/_next/static/`. في 2026-10-08 كان Go يعيد ستة كتب بينما أعاد خادم Next.js بعض ملفات JavaScript بحالة 404 بعد تشغيل البناء بالتزامن مع خادم التطوير؛ عادت الملفات بحالة 200 بعد إعادة تشغيل `npm run dev`. يجب إيقاف خادم التطوير قبل `npm run build` لأن الأمرين يشتركان في `.next`.

ظهر عند أحد المتصفحات اختلاف في خاصية `fdprocessedid` على حقل البحث. هذه الخاصية غير موجودة في كود الواجهة ولا في HTML الذي يرسله الخادم؛ تشير الأدلة إلى تعديل الحقل داخل المتصفح قبل تحميل React، مثل إضافة متصفح. للتأكد، افتح الموقع في نافذة خاصة دون إضافات أو عطّل الإضافات لهذا الموقع ثم أعد التحميل. لا تستخدم `suppressHydrationWarning` لإخفاء الفرق قبل تحديد مصدره. راجع [شرح Next.js الرسمي](https://nextjs.org/docs/messages/react-hydration-error).
