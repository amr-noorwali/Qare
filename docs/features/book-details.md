# صفحة تفاصيل الكتاب

توثيق التنفيذ داخل مشروع الواجهة: [frontend/docs/features/book-details.md](../../frontend/docs/features/book-details.md).

## الحالة الحالية

الصفحة العامة `/books/[id]` تعرض الغلاف، العنوان، المؤلف، النوع، النبذة، متوسط التقييم، عدد المراجعات ونصوصها. تعرض حالة تحميل أو رسالة إذا لم يوجد الكتاب. عند دخول المستخدم يظهر اختيار تصنيف الكتاب في مكتبته ونموذج مراجعة.

أصبح عرض الصفحة أحادي اللون بتباين واضح، وغلاف بدرجات الرمادي، ولوحة زجاجية لنموذج المراجعة. لم تتغير بيانات الكتاب أو الطلبات.

## مسار العمل والارتباطات

في الفرونت، صفحة `app/books/[id]/page.tsx` تحمل حاليًا حالة التفاصيل والمراجعات والتصنيف في ملف واحد، وتستخدم `components/ui/button.tsx` و`lib/api.ts`. لا توجد مكونات منفصلة لهذه الأقسام بعد؛ راجع [خريطة الفرونت إند](frontend-map.md).

بطاقة الكتاب في `frontend/components/book-card.tsx` → `frontend/app/books/[id]/page.tsx` → `books.get(id)` في `frontend/lib/api.ts` → `GET /api/books/{id}` → `Book` في `backend/internal/handlers/api.go` → `OneBook` و`Reviews` في `backend/internal/repositories/books.go`.

يعيد الـAPI كائنًا بالشكل `{book,reviews}`. الغلاف يأتي من `books.cover_url`، والمتوسط والعدد يُحسبان من جدول `reviews` عند القراءة. الصفحة تقرأ المستخدم الحالي ومكتبته بعد التحميل لتحدد مراجعة المستخدم وتصنيف الكتاب. لذلك ترتبط مباشرة بملفي [المراجعات](reviews-ratings.md) و[المكتبة](personal-library.md)، وتعتمد حالتهما المحمية على [المصادقة](authentication.md).

## API والبيانات

- `GET /api/books/{id}` عام؛ يعيد تفاصيل الكتاب والمراجعات مرتبة بالأحدث، أو 404 إن لم يوجد.
- جدول `books`: `id`, `title`, `author`, `description`, `cover_url`, `genre`.
- جدول `reviews` يزود النصوص والمتوسط والعدد؛ جدول `library` يزود حالة المستخدم فقط عند الدخول.

## غير موجود أو غير مكتمل

- لا يوجد تحرير بيانات الكتاب أو رفع غلاف من الصفحة.
- لا توجد صفحات للمراجعات إذا كثر عددها؛ تُحمّل كلها.
- الغلاف يعتمد رابطًا خارجيًا؛ قد لا يظهر إذا تعطل المصدر.
