# التسجيل والدخول والجلسات

توثيق التنفيذ داخل مشروع الواجهة: [frontend/docs/features/authentication.md](../../frontend/docs/features/authentication.md).

## الحالة الحالية

تعمل في الـMVP. يستطيع الزائر إنشاء حساب، تسجيل الدخول، واستعمال الميزات المحمية. ينشئ الباك إند رمز جلسة محفوظًا في SQLite لمدة 30 يومًا. تحفظه الواجهة حاليًا في `localStorage` تحت المفتاح `qare_token`، وترسله في ترويسة `Authorization: Bearer <token>`.

تستخدم صفحتا الدخول والتسجيل الآن لوحة زجاجية أحادية اللون مع صورة مكتبة محلية في الخلفية، ويظهر اسم المنصة «قارئ» بجانب الشعار. تدخل اللوحة بحركة CSS خفيفة وتستجيب أزرارها عند التفاعل، وتتوقف الحركة مع تفضيل تقليلها. النصوص والحقول والأزرار تتبع مقياس الخط المركزي في [الهوية البصرية](visual-identity.md). بقيت شروط التسجيل وتدفق الجلسة كما هي.

## مسار العمل

1. نموذجا `/register` و`/login` يستخدمان `AuthForm`.
2. `frontend/lib/api.ts` يرسل بيانات التسجيل/الدخول إلى Go ويتلقى `{user,token}`.
3. `services/auth.go` يتحقق من المدخلات وينشئ تجزئة bcrypt ورمز الجلسة؛ `repositories/auth.go` يحفظ المستخدم والجلسة في SQLite.
4. المسارات المحمية تمر عبر `Require`، الذي يتحقق من الرمز وتاريخ صلاحيته قبل تنفيذ المعالج.
5. الترويسة تستدعي `/auth/me` عند تحميلها إذا وجدت رمزًا. بعد نجاح التسجيل أو الدخول تنتقل الواجهة إلى `/library`.

التحقق الحالي: الاسم بعد إزالة الفراغات لا يقل عن بايتين، البريد يحتوي `@` ويكون فريدًا، وكلمة المرور لا تقل عن 8 بايتات. حقل البريد في المتصفح يستخدم `type=email`. لا يوجد تأكيد للبريد. حساب `demo@qare.local` مخصص لعرض مراجعات أولية وليس له كلمة مرور صالحة للدخول.

## الارتباطات

في الفرونت، `page.tsx` للربط بالمسار فقط؛ `AuthForm` ينفذ الحقول والإرسال، و`Header` يعرض حالة المستخدم، و`lib/api.ts` يجمع طلبات الدخول. راجع [خريطة الفرونت إند](frontend-map.md) لكل الملفات والحالة.

| الطبقة | الموضع |
|---|---|
| صفحات الواجهة | `frontend/app/register/page.tsx`, `frontend/app/login/page.tsx` |
| النموذج والترويسة | `frontend/components/auth-form.tsx`, `frontend/components/header.tsx` |
| عميل الـAPI | `frontend/lib/api.ts` (`auth`, `token`, `api`) |
| المسارات والمعالجات | `backend/internal/routes/routes.go`, `backend/internal/handlers/auth.go`, `base.go` |
| منطق الدخول | `backend/internal/services/auth.go` |
| استعلامات الدخول والجلسات | `backend/internal/repositories/auth.go` |
| مخطط قاعدة البيانات | `users`, `sessions` في `backend/internal/repositories/migrations.go` |
| الميزات التابعة | [المراجعات](reviews-ratings.md)، [المكتبة](personal-library.md) |

## API

| الطريقة والمسار | النتيجة |
|---|---|
| `POST /api/auth/register` | ينشئ حسابًا وجلسة؛ يعيد 201 و`{user,token}` |
| `POST /api/auth/login` | يتحقق من البيانات؛ يعيد 200 و`{user,token}` أو 401 |
| `GET /api/auth/me` | يعيد المستخدم الحالي؛ يتطلب رمزًا صالحًا |
| `POST /api/auth/logout` | يحذف الجلسة ويعيد 204؛ يتطلب رمزًا صالحًا |

## غير موجود أو غير مكتمل

- زر الخروج في الواجهة يمسح الرمز محليًا فقط؛ لا يستدعي `/api/auth/logout`، ولذلك تبقى الجلسة في قاعدة البيانات حتى تنتهي صلاحيتها.
- لا يوجد تأكيد بريد، استعادة كلمة مرور، حد لمحاولات الدخول، أو Cookie محمية `HttpOnly`. هذه نقاط مطلوبة قبل استخدام إنتاجي عام.
- التحقق من الاسم والبريد في Go بسيط، ويحسب طول النص بالبايتات.
