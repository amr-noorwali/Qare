# قاعدة البيانات وREST API والإعدادات

## الحالة الحالية

المشروعان مستقلان: Next.js في `frontend/` وGo في `backend/`. الواجهة تتواصل مع Go عبر HTTP/JSON فقط. يستخدم Go `net/http` وMySQL 8 عبر `go-sql-driver/mysql`؛ يتطلب `MYSQL_DSN`، وينشئ الجداول داخل قاعدة MySQL موجودة مسبقًا. تُتبع هجرات المخطط في `schema_migrations`. يضيف ستة كتب ومراجعتين إلى قاعدة بلا كتب داخل معاملة. اسم حساب المراجعات التجريبي «قارئ من منصة قارئ»؛ الحساب غير مخصص للدخول. مكتبة SQLite باقية فقط في أداة استيراد البيانات القديمة.

النشر الحالي: الواجهة على `https://qare-eta.vercel.app`، وواجهة REST على `https://qare-api.onrender.com/api`، وقاعدة MySQL مستضافة في Aiven. نُقلت بيانات MySQL المحلية إلى Aiven، ويقرأ Render إعدادات الاتصال من أسراره وشهادة CA من ملف سري. تحقق اختبار REST عام من التسجيل والدخول والكتاب والمراجعة والمكتبة والخروج، ثم حُذف حساب الاختبار. اتصال GitHub التلقائي بمشروع Vercel لم ينجح بعد؛ نُشرت الواجهة بأداة Vercel CLI، ونُشر الباك إند يدويًا بأداة Render CLI.

## مسار الطلب

لخريطة أدق للفرونت من الصفحة إلى المكون وخدمة REST، راجع [خريطة الفرونت إند](frontend-map.md). هذه الطبقة لا تملك صفحات مستقلة؛ يستخدمها كل مسار عبر `lib/api.ts`.

`frontend/app` → `frontend/lib/api.ts` → `http://localhost:8080/api` → `backend/internal/routes/routes.go` → `backend/internal/handlers/{auth,books,reviews,library}.go` → `backend/internal/services/` عند وجود قواعد عمل → `backend/internal/repositories/` → MySQL.

الـhandlers مسؤولة عن HTTP فقط؛ خدمات المصادقة والمراجعات والمكتبة تتحقق من القواعد، وكل SQL في repositories. استعلامات القراءة المباشرة تستخدم repositories من الـhandler لأن لا منطق عمل إضافيًا لها. ملفات المخطط والبيانات الأولية منفصلة عن استعلامات الميزات؛ أضف الهجرات الجديدة بترتيبها دون تعديل السابقة.

## الجداول والعلاقات

| الجدول | الدور والعلاقة |
|---|---|
| `users` | بيانات المستخدم والبريد الفريد وتجزئة كلمة المرور |
| `sessions` | رمز الجلسة، المستخدم المرتبط، وتاريخ الانتهاء |
| `books` | بيانات الكتب والغلاف والنوع |
| `reviews` | مراجعة المستخدم للكتاب؛ تقييم 1–5 ومراجعة واحدة لكل زوج مستخدم/كتاب |
| `library` | تصنيف كتاب واحد لكل مستخدم؛ `want`, `reading`, `read` |

مفاتيح العلاقات الأجنبية مفعلة، والفهارس الإضافية موجودة للمراجعات حسب الكتاب والتاريخ، والمكتبة حسب الكتاب، والجلسات حسب المستخدم. متوسط التقييم وعدد المراجعات يُحسبان في استعلامات القراءة ولا يُخزنان في `books`.

## نقاط REST الـ11

| المجال | النقاط |
|---|---|
| المصادقة | `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` |
| الكتب | `GET /books`, `GET /books/{id}` |
| المراجعات | `PUT /books/{id}/review`, `DELETE /books/{id}/review` |
| المكتبة | `GET /library`, `PUT /library/{id}`, `DELETE /library/{id}` |

أضف `/api` قبل كل مسار في الجدول. تفاصيل الأجسام والأكواد في `backend/README.md`، واستخدام الواجهة في `frontend/lib/api.ts`. المسارات المحمية تستخدم Bearer token. الأخطاء المعتادة تعيد `{ "error": "..." }`.

## الإعدادات والتشغيل

- `backend/.env.example`: `PORT=8080`, `MYSQL_DSN=qare:change-me@tcp(127.0.0.1:3306)/qare`, `FRONTEND_ORIGIN=http://localhost:3000`. يقرأ Go **متغيرات البيئة الفعلية** ولا يحمّل ملف `.env` تلقائيًا. يجب إنشاء قاعدة MySQL أولًا.
- على جهاز Windows الحالي تعمل `MySQL80` على `3307` وتعمل MariaDB على `3306`. يساعد `backend/scripts/setup-local-mysql.ps1` على إعداد حساب محلي مخصص للمنصة وكتابة `backend/.env` بعد تشغيله بصلاحية مسؤول؛ لا يغيّر SQLite القديمة.
- `frontend/.env.example`: `NEXT_PUBLIC_API_URL=http://localhost:8080/api`، وهذا هو الافتراضي أيضًا.
- شغّل `go run .` من `backend/`، و`npm run dev` من `frontend/`. تحقق من Go بـ`go test ./...` ومن الواجهة بـ`npm run lint` و`npm run build`.
- ملف SQLite المحلي القديم `backend/qare.db` يبقى للنسخ الاحتياطي والنقل ولا يستخدمه API الجديد. أداة `backend/cmd/importsqlite` تنسخ الجداول الخمسة إلى MySQL فارغة، مع الحفاظ على المعرفات والجلسات وكلمات المرور المشفرة؛ راجع `backend/README.md` للخطوات.

## غير موجود أو غير مكتمل

- توجد هجرات MySQL مرقمة داخل Go، لكن لا توجد أداة تراجع تلقائي للهجرات أو نسخ احتياطي تلقائي أو إعداد نشر إنتاجي كامل.
- لا يوجد ترقيم صفحات في API، ولا حد معدل للطلبات. تظل مراقبة قاعدة البيانات والنسخ الاحتياطي إعدادات مطلوبة لدى مزود الاستضافة.
